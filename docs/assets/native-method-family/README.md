# Accepted native method recognition family

4 October 2026. `tools/import_approved_method_vectors.cjs` projects the accepted
prototype's 17 method symbols plus its generic wedge into Android. It preserves
every contour, the 24-unit viewport and even-odd winding; Material content tint
supplies color. `manifest.json` binds both the prototype bytes and native exports.
Text hashes use UTF-8 with LF, so Windows checkout line endings do not invalidate
an otherwise identical export.

Pulsar uses the later user-approved generated export from canonical commit
`2fff9e14`, retained here as `pulsar-approved.xml`. The importer copies those bytes
unchanged. The prototype's earlier Pulsar shape is deliberately not imported.
Its original generation, vector and native-size evidence is in canonical main's
`docs/assets/pulsar-imagegen-vector/README.md` at that commit.

These are decorative recognition symbols beside method/profile labels. They
are not instructions, hardware schematics, or approval of any instruction scene.
The exact instruction image/hash release gate is unchanged. The same symbol is
used in the calculator's equipment controls and the Learn library. Known single
cup and non-pump espresso variants use the approved neutral vessel symbols;
unknown profiles get a neutral cup rather than invented brewer geometry.

The thirteen replaced Learn recognition WebPs are retained byte-for-byte under
`previous-learn-recognition/`, with their original paths and hashes. Historical
generation records keep their original path text; archived pixels are the
reproduction source now. Instruction illustrations, filters and grinder artwork
are not replaced. The older equipment tracer verifies and skips accepted method
resources, so regeneration cannot overwrite this family with older candidates.

```powershell
node tools/import_approved_method_vectors.cjs --check
```

The source geometry is accepted prototype artwork. Native rendering and small-
size evidence is recorded in the native integration review after verification.
