## Implementation conventions

### Stable identity

- `StageId`: `p1_<recipe_id>_<source_stage_id>`.
- `StageContentId`: `<StageId>_instruction`.
- `StageObservationId`: `p1_obs_<recipe_id>_<source_stage_id>` for an
  observation-driven completion.
- `StageTargetId`: `p1_target_<recipe_id>_<source_stage_id>_time_<n>`,
  where `<n>` follows the typed time-reference order shown in the row.
- Proposed exact default asset: `instruction_<StageContentId>_default`.

Identity is recipe-and-source-stage scoped. Similar actions in different
recipes do not share semantic IDs because their equipment state, timing,
warning, or observable completion can differ.

### One completion trigger, independent references

Each row has exactly one proposed `StageCompletionMode`. Time, mass, and
temperature remain independent `StageReferenceTargets`; displaying a
reference never makes it a second completion condition.

- Observation is the trigger whenever the source completes on drawdown,
  saturation, settling, foam rise, first/last drip, valve flow, or machine
  completion. A nearby time remains guidance only.
- Countdown is used only where elapsed time is itself the source completion:
  the official Switch two-minute steep and the retained 40-second hybrid
  bloom.
- Exact cumulative mass is a trigger only when the source completes on the
  scale reading. Approximate mass is not silently converted to an exact
  auto-advance threshold.
- Manual completion covers preparation, service, and current model gaps.
  It does not erase the source cue, which remains recorded in the row.
- `Immediate`, `ElapsedRange`, `AddedAmount`, `BeverageYield`, and
  `ExternalMarker` are not needed by this exact source selection.

### Typed-target fidelity and model gaps

- Typed targets are transcriptions of explicit source values. Raw source
  fields are retained beside them so qualifiers and conditions remain
  auditable.
- Current mass kinds cover only added water, cumulative water, and beverage
  yield. Coffee dose, brew ice, reservoir input, and a marked fill level
  are labelled `SOURCE_ONLY`; they require a future typed-kind extension
  rather than misclassification.
- A recipe-level temperature is attached only to a stage that adds or heats
  brew water. Machine-controlled, cold-start, or otherwise nonnumeric
  source statements remain source-only.
- Two timing shapes need a future model extension: a time attached to a
  sub-action within a composite stage, and multiple observation-cue times
  whose clock basis is not explicit. Those values remain visible but are
  not coerced into the current references.
- `NO_LATER_THAN 1 s` for the Rao settling spin is only the closest current
  representation of the stricter source wording “less than one second”;
  the raw wording remains authoritative.

### Warning normalization

The source has warning text and visual priority but no warning severity
enum. The proposed deterministic projection is `CRITICAL` only for
canonical `safety-critical` visual priority, `WARNING` for any other
nonempty source warning, and `NONE` otherwise. This is implementation
normalization, not a
new source claim.

### Illustration placement, status, and blocker codes

`P1-STAGE-CARD` means both exact placements: in Learn, inside the ordered
stage card immediately after its instruction; in Live Brew, inside the
current-stage Guidance card after instruction and safety copy. Both use a
full-width 4:3 viewport with `ContentScale.Fit`. Text, amounts, timers,
temperature, and warnings remain Compose content, never bitmap content.

The production tracker currently records 38 accepted exact-stage assets and 76 open assets. Accepted candidates remain subject to the separate runtime,
accessibility, localization, and release gates; open assets remain
`NOT_PRODUCED`.
