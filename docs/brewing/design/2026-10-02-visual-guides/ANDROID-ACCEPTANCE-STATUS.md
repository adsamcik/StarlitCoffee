# Native guide acceptance status

4 October 2026. The native implementation of the [approved plan](ANDROID-IMPLEMENTATION-PLAN.md) is complete. This records development acceptance and its evidence boundaries; it is not a release declaration. Detailed evidence and earlier fixes remain in [NATIVE-INTEGRATION-REVIEW.md](NATIVE-INTEGRATION-REVIEW.md).

| Requirement | Delivered behavior and verification | Validation boundary |
| --- | --- | --- |
| Existing UI integration | Calculator cards, set/ratio selectors, vessel shortcuts and keypad are retained. Brew/Log/More and adaptive navigation are retained; Learn opens through More. Guides use the existing Material 3 theme and dynamic/dark colors. Native calculator, preparation, More and Learn walkthroughs passed. | Physical-device and complete TalkBack speech review remain external acceptance. |
| Approved vessels and methods | All 28 approved vessel vectors and 18 monochrome method glyphs preserve reviewed geometry, winding, tint and aliases. The later approved native Pulsar is retained. Native small-size light/dark renderer checks passed. | Recognition assets do not approve instruction mechanics. |
| Shared app activity | Root activity strip is absent when empty, opens one session directly, and presents a chooser for multiple sessions. Reached reminders take priority; the focused brew is hidden while other sessions remain accessible. Root projection tests and a live two-session walkthrough passed. | Full navigation-state restoration on every physical device is not claimed. |
| Visual guide surface | Brew and Learn share the action canvas, quantity/time targets, visible step-specific safety, Done when and cohesive Why disclosure. Exact approved instruction scenes are reused where their identity matches. Other reviewed methods use the approved recognition badge with accurate source instructions. Narrow 200% dark reader and native screen review passed. | Additional detailed instruction illustrations require their own asset approval. No candidate image is presented as approved mechanics. |
| Untimed learning and read-ahead | All steps, equipment, sources, variants, troubleshooting and uncertainties are reachable. Reading bookmarks are independent of brewing. Room/state checks prove unchanged stage, observations, clock and targets during reading. The actual AeroPress walkthrough read step 2 and returned to unchanged preparation step 1. | Technical source text is explicitly English in other locales; interface controls are localized. |
| Chemex identity | Existing chemex_42_700 remains exactly 42 g / 700 g with seven stages. Reviewed 30 g / 480 g has a separate recipe/content identity and eight source steps. Exact-identity and native reader checks passed. | No substitution for arbitrary calculator quantities or incompatible equipment. |
| Seventeen methods | Native equipment-scoped presets cover Chemex, automatic drip, Pulsar, V60, Clever, Hario Switch, Kalita Wave, Melitta, Turkish, phin, French press, AeroPress, espresso, moka pot, cold brew, siphon and percolator. All source procedures retain frozen provenance, quantities, clock origins, completion criteria and applicable safety. Export checks and all-method execution/recovery checks passed. | Recipes apply to their stated equipment, not every variant. Research is editorially reviewed, not a physical brewing trial. |
| Truthful quantities and history | Volume stays mL; espresso cup yield is not water input. Fill-to-mark recipes require actual weighed coffee and accept optional weighed water. Absent water/ratio is explicit and omitted from log/share displays. Snapshot validation retains legacy defaults and guards source mismatch. | No invented basket mass, beverage yield or mass ratio. |
| Preparation and coffee memory | Room 20→21, physical pack identity, coffee/barcode identity and scoped grind memory are integrated. One resolver uses temporary → pack → coffee → type with grinder compatibility. Session/log snapshots freeze selected coffee and compatible grind. Reviewed Pulsar uses the Gagné source procedure in the shared owner/canvas. Migration, memory, calculator persistence and preparation tests passed. | Legacy standalone journey paths remain compatibility paths; fresh app starts use the shared owner. |
| App-owned clocks | Every current calculator method and all 17 source presets run through the same durable coordinator. Preparation waits for the recipe's physical origin; elapsed extraction survives route changes and process recreation. Completion remains physical/manual. A real Pulsar process restart retained the original clock. | Compatibility data is retained; process recovery is not evidence of hardware reboot delivery. |
| Guide pause | Pause guide persists separately, suppressing discretionary guidance cues while physical clocks, explicit user reminders and quiet OS status continue. Existing explicit Pause timer compatibility remains. State, Room, actual notification and process restart checks passed. | Timer expiry never operates a pump, valve or burner. |
| Cold-brew Start | Existing Start owns Follow guide / Just set timer, a refrigerated 14-hour default, configurable duration, actual/earlier/unknown origins and explicit filtration. Unknown origins have no estimated deadline. Timer-only ending creates no stock deduction or brew log. Native Start and persistence checks passed. | Time/appearance never certify food safety; refrigeration guidance stays visible. |
| Custom reminders | All methods accept a contextual persisted target with stage, revision, original elapsed origin and deadline. Editing retains elapsed time and cancels obsolete effects. Expiry requires checking the brew and never auto-completes it. All-method recovery and actual OS cue checks passed. | Android permission/channel denial degrades alerts without stopping a brew. |
| Notifications and scheduling | Quiet OS chronometers, actionable due cues and exact-session intents share the same persisted owner. Distinct session identities, obsolete-cue withdrawal, durable at-most-once attempts and serialized delivery are verified. AlarmManager uses precise access when allowed, with WorkManager recovery and reboot/package/clock-change reconciliation. Actual emulator alarm and revision-cancellation checks passed. | Real-device punctuality, deep Doze, actual reboot delivery and the crash window of an at-most-once notification attempt remain explicit limits. |
| Delivery | Debug app/test APKs, detekt, focused JVM checks, native UI/Room/OS/alarm checks and guide export checks pass. Feature-owned translations/lint issues are corrected. Changes are selectively committed without a release/version bump. | Full lint still reports the documented baseline findings; the repository is not declared release-ready. |

The plan's implementation work is closed. Remaining validation is professional technical localization, physical brewing trials, real-device timing/reboot behavior, and complete speech/adaptive-device review. These are not represented as passing by emulator, build or source checks.

Android platform references: [notification chronometers](https://developer.android.com/reference/androidx/core/app/NotificationCompat.Builder), [WorkManager delays](https://developer.android.com/develop/background-work/background-tasks/persistent/getting-started/define-work), [alarm scheduling](https://developer.android.com/develop/background-work/services/alarms).
